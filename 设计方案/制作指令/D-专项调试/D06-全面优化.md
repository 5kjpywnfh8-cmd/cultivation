# 全面优化指令

对当前项目做全面优化，覆盖代码质量、性能、UI/UX、数值平衡等方面。

【优化维度】

一、代码质量优化
1. 提取公共函数：消除重复代码（如 addToInventory、格式化函数）
2. 统一命名规范：文件名/变量名/函数名风格一致
3. 类型安全：消除 any 类型，补充缺失的类型定义
4. 注释完善：关键函数添加 JSDoc，复杂逻辑添加行内注释
5. 错误处理：边界情况处理、空值检查、异常捕获
6. 代码组织：相关功能聚合，导入路径清晰

二、性能优化
1. 减少重渲染：使用 computed 缓存计算结果，避免不必要的响应式更新
2. 优化大列表：虚拟滚动或分页，避免一次性渲染大量 DOM
3. 减少内存分配：复用对象，避免在循环中创建新对象
4. 节流/防抖：频繁操作（如点击、输入）使用节流/防抖
5. 惰性加载：非首屏内容延迟加载
6. 配置冻结：config 加载后 Object.freeze 防止意外修改

三、UI/UX 优化
1. 加载态：数据加载时显示骨架屏或加载动画
2. 空态：列表为空时显示友好提示
3. 错误态：操作失败时显示明确错误信息
4. 交互反馈：按钮点击、操作成功/失败的视觉反馈
5. 动画效果：页面切换、数值变化的平滑过渡
6. 响应式：PC/平板/手机三端布局适配
7. 无障碍：键盘导航、焦点管理、aria 属性

四、数值平衡优化
1. 战斗数值：检查伤害公式、Boss血量、掉落概率是否合理
2. 经济数值：检查货币产出/消耗是否平衡
3. 时间节奏：检查升级/打造/生产的耗时是否合理
4. 边界情况：极端数值（0资源、满背包、最高等级）的处理

五、存档优化
1. 存档体积：排除默认值字段，减少序列化体积
2. 迁移兼容：新版本存档能正确加载旧版本数据
3. 备份策略：备份数量、清理策略
4. 导入/导出：格式校验、错误提示

【优化规则】
- 不改变功能和外部行为
- 优化后必须验证功能正常
- 避免过早优化，只优化实际有问题的部分
- 每项优化记录改了什么、为什么改
- 优化后重新审查，确认不引入新问题

【审查维度】
1. 功能正确性：优化后功能是否完全不变
2. 性能提升：是否有可测量的性能改善
3. 代码质量：是否更易读、易维护
4. 兼容性：是否影响其他模块
5. 存档安全：是否影响存档读写

【输出要求】
- 列出所有优化项（按优先级排序）
- 每项说明：问题描述、优化方案、涉及文件
- 优化后验证结果
- 最终优化总结
