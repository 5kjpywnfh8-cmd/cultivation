# 设计文档更新指令

实现过程中发现设计文档与实际代码不符时，系统性更新文档。

---

更新设计文档：

【触发条件】
- 实现确实无法按原文档执行（技术限制、架构调整）
- 发现文档遗漏（新增字段、新增配置、新增系统）
- 数值/公式经过验证后需要修正
- 文件路径/命名与实际项目结构不符

【第一步：差异识别】
对比以下维度，列出所有差异：

1. 配置表索引（00-总览.md 第十节）
   - 列出 src/config/ 下实际存在的 JSON 文件
   - 与设计文档预期的配置表对比
   - 标记：已实现 / 待实现 / 路径变更

2. PlayerState 接口（补充-存档数据结构.md）
   - 读取 src/core/GameState.ts 的 PlayerState 定义
   - 与设计文档的 PlayerState 对比
   - 标记：新增字段 / 删除字段 / 类型变更

3. 系统模块（各系统设计文档）
   - 列出 src/systems/ 下实际存在的系统文件
   - 与设计文档预期的系统对比
   - 标记：已实现 / 待实现 / 功能裁剪

4. 数值公式（补充-数值公式统一.md + 各系统文档）
   - 对比代码中的实际公式与设计文档公式
   - 标记：一致 / 已调整（附原因）

【第二步：必要性判断】
每个差异需要判断：

| 类型 | 处理方式 |
|------|----------|
| Bug修复导致的架构调整 | 必须更新（如 baseStats 解决属性膨胀） |
| 实现细节优化 | 可选更新（如工具函数抽取） |
| 功能延后实现 | 标注状态即可（如成就系统待Phase 3） |
| 路径/命名变更 | 必须更新（影响开发者查找） |

【第三步：执行更新】
按文档依赖顺序更新：

1. 补充-存档数据结构.md（PlayerState 接口）
   - 新增/删除/修改字段
   - 新增接口定义（如 BaseStats）
   - 附注设计原因（为什么新增、解决什么问题）

2. 00-总览.md 第十节（配置表索引）
   - 分"已实现"和"待实现"两表
   - 修正 JSON 路径（src/config/ 而非 config/）
   - 合并/拆分配置项（如 Boss+怪物共用一个文件）

3. 各系统设计文档（如有公式/常量变更）
   - 更新数值表
   - 更新公式
   - 附注变更原因

4. 补充-数值公式统一.md（如有数值变更）
   - 同步更新权威公式
   - 标注"已验证"或"待验证"

【第四步：影响范围检查】
更新后检查：

- 其他文档是否引用了被修改的段落/字段名
- 制作指令是否需要同步更新
- 配置表索引是否完整（无遗漏、无重复）
- 新增接口是否有对应的默认值工厂（createNewPlayerState）

【输出要求】
- 更新的文档和具体段落
- 更新前后的对比（原文 → 新文）
- 影响范围分析（哪些文档/代码受影响）
- 构建验证（npm run build 通过）

开始。
