## 第一阶段：AI 自动审查（20个维度）

分6批执行，每批聚焦一个维度类别。

### 批次 A：功能与数据（4维度）

**A1. 功能正确性**
```
对21个系统逐个检查：
- 每个 public 方法的逻辑是否符合设计文档
- 返回值是否正确
- 异常路径是否处理
- 边界条件（空输入、0值、负值、溢出）
```

**A2. 数据一致性**
```
对比代码中的公式/常量与设计文档：
- realm-stats.json 60级属性表
- enhance-config.json 强化公式
- monster-templates.json Boss属性
- equipment-templates.json 品质系数
- skill-templates.json 技能倍率/冷却
- shop-config.json 商品价格
```

**A3. 配置完整性**
```
检查10个JSON配置文件：
- 所有 ID 引用是否一致（无孤立引用）
- 必填字段是否完整
- 数值范围是否合理（无负数攻击、无0成功率等）
- 枚举值是否匹配 TypeScript 类型定义
```

**A4. 核心循环完整性**
```
走通完整链路：
修炼（RealmSystem）→ 采集（ResourceSystem）→ 打造（EquipmentSystem）
→ 强化（EnhanceSystem）→ 战斗（CombatSystem）→ 商店（ShopSystem）
→ 存档（SaveSystem）

验证每个环节的输入输出是否衔接正确。
```

### 批次 B：架构与集成（4维度）

**B5. 跨模块一致性**
```
检查模块间接口：
- 事件名是否统一（EventBus emit/on 匹配）
- 类型定义是否共享（从 GameState.ts 导入）
- 方法签名是否一致（调用方 vs 被调用方）
- 枚举值是否统一（PlanetId、EquipmentSlot 等）
```

**B6. 事件系统完整性**
```
检查 EventBus 所有事件：
- 列出所有 emit() 调用
- 列出所有 on() 订阅
- 验证每个 emit 都有对应 on
- 检查监听器清理（off/once）
- 检查事件顺序依赖
```

**B7. 系统集成**
```
检查21个系统的初始化：
- App.vue 中的初始化顺序是否正确
- 依赖注入是否完整（构造函数参数）
- GameLoop 注册是否完整（update/beforeSave/afterLoad）
- 循环依赖是否存在
```

**B8. 类型安全**
```
TypeScript 严格检查：
- 搜索所有 `as any` 并消除
- 检查 null/undefined 处理
- 枚举穷尽检查（switch 是否有 default）
- 泛型类型参数是否正确
```

### 批次 C：存档与离线（3维度）

**C9. 存档安全**
```
检查 SaveSystem：
- PlayerState 所有字段是否序列化
- 版本迁移链路（v0→v1→v2）
- 存档损坏恢复（备份机制）
- 默认值合并（字段缺失时的 fallback）
```

**C10. 离线收益正确性**
```
检查离线计算：
- 时间戳精度（毫秒级）
- 离线时长上限（8h/16h/24h/32h 按境界）
- 多资源并行计算
- 离线奖励合并到 PlayerState
```

**C11. 存档兼容性**
```
检查向后兼容：
- 新增字段是否有默认值
- 删除字段是否有迁移处理
- 嵌套对象结构变更是否有兼容逻辑
```

### 批次 D：UI与交互（3维度）

**D12. UI/UX**
```
检查11个Vue组件：
- 加载态（数据未就绪时）
- 空态（无数据时的提示）
- 错误态（操作失败的反馈）
- 交互反馈（按钮点击、操作成功提示）
- 信息密度（关键数据是否可见）
```

**D13. 移动端适配**
```
响应式检查：
- 触摸目标尺寸（≥44px）
- 文字不溢出
- 按钮不挤压
- 表格/列表可滚动
- 安全区域处理
```

**D14. 管理员模式安全**
```
检查 AdminSystem：
- Admin 面板是否仅在开发环境可用
- ~键快捷键是否与其他功能冲突
- 管理员命令是否有确认机制（危险操作）
```

### 批次 E：性能与稳定性（3维度）

**E15. 性能**
```
- 不必要的响应式更新（computed/watch 滥用）
- 大数组/对象的响应式开销
- 定时器清理（setInterval/setTimeout）
- 事件监听器清理
```

**E16. 长期运行**
```
挂机场景模拟：
- ScientificNumber 对象创建/销毁频率
- GameLoop 帧率稳定性（dt clamping）
- 内存增长趋势（对象泄漏）
- 定时器数量是否稳定
```

**E17. 边界处理**
```
- 货币为0/负数时的操作
- 背包满时的添加
- 怪物死亡瞬间的状态
- 强化+0/+1 边界
- 科学计数法溢出
```

### 批次 F：系统专项（3维度）

**F18. 战斗系统**
```
- Boss 技能/状态效果是否正确
- 副本层数推进和扫荡
- 强化公式和失败惩罚
- 词条生成权重和数值范围
```

**F19. 生产经营**
```
- 星球资源产出和天气加成
- 生产队列和批量生产
- 灵田种植和收获
- 运输航线和货物管理
```

**F20. 成长辅助**
```
- 技能学习/升级/进化流程
- 科技树研究和效果应用
- 新手引导步骤和持久化
```

## 执行流程

```
┌─────────────────────────────────────────────────┐
│  第一阶段：AI 自动审查                             │
│                                                   │
│  批次A → 批次B → 批次C → 批次D → 批次E → 批次F    │
│  (每批次输出问题清单，按严重程度排序)                │
│                                                   │
│  ↓ 问题清单                                       │
│                                                   │
│  修复循环：发现问题 → 修复 → 重新审查 → 直到无问题  │
│                                                   │
├─────────────────────────────────────────────────┤
│  第二阶段：人工浏览器测试                           │
│                                                   │
│  核心循环(10项) → 边界测试(5项) → UI测试(4项)      │
│                                                   │
│  ↓ 测试结果                                       │
│                                                   │
│  修复循环：发现问题 → 修复 → 重新测试 → 直到通过    │
│                                                   │
├─────────────────────────────────────────────────┤
│  最终输出                                          │
│                                                   │
│  - 审查结论（通过/不通过）                          │
│  - 问题统计（致命/重要/轻微/已修复）                │
│  - 代码统计（行数/文件数/系统数）                   │
│  - 已知遗留项                                      │
└─────────────────────────────────────────────────┘
```

## 问题严重程度定义

| 级别 | 定义 | 处理 |
|------|------|------|
| 🔴 致命 | 数据丢失、存档损坏、核心循环不可用 | 立即修复，阻塞发布 |
| 🟡 重要 | 功能缺失、数值错误、UI严重异常 | 当前批次修复 |
| 🟢 轻微 | 命名不规范、缺少注释、小UI问题 | 记录，可延后 |
| ⚪ 建议 | 优化建议、体验改进 | 记录，不阻塞 |

开始。
