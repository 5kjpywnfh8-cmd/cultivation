# Phase 1 MVP 完整执行指令

按 Phase 1 MVP 制作计划执行，规则如下：

【执行规则】
- 从 1.1.1 开始，严格按任务编号顺序逐个子任务执行
- 严格按设计文档的数值、公式、逻辑实现，不自行发挥
- 优先参考 制作计划/05-技术架构.md 的架构设计
- 数值冲突时以 补充-数值公式统一.md 为准
- 存档结构以 补充-存档数据结构.md 为准
- UI 以 补充-UI布局设计.md 为准
- 参考 审查报告/总结报告.md 中110个已发现问题，避免重复引入

【审查规则】
- 每完成一个子任务：审查 → 修复 → 循环到该子任务无问题
- 每完成一个模块：模块整体审查 → 修复 → 循环到该模块无问题
- Phase 1 全部完成后：整体审查 → 修复 → 循环到无问题

【审查维度（每轮必须覆盖）】
1. 功能正确性：逻辑是否符合设计文档，边界情况是否处理
2. 数据一致性：数值/公式/配置是否与设计文档一致
3. 系统集成：事件总线通信是否正确，模块间依赖是否满足
4. 存档安全：存档/读档/迁移是否完整，离线收益是否正确
5. UI/UX：响应式布局、加载态、空态、错误态、交互反馈
6. 代码质量：命名规范、注释、错误处理、无硬编码
7. 性能：无必要重渲染、内存泄漏、死循环风险

【验证规则】
- 每个子任务完成后，确认代码可编译无报错
- 每个模块完成后，启动项目验证该模块功能可正常运行
- 全部完成后，完整走一遍核心循环（修炼→采集→打造→战斗→商店→存档）

【问题升级】
- 发现设计文档矛盾/缺失：暂停，报告问题，等确认再继续
- 需要改已通过审查的模块：记录依赖关系，按顺序修复

【进度跟踪】
- 用任务列表实时显示59个子任务完成状态
- 每个子任务标记：待执行/进行中/审查中/已完成

【输出要求】
- 每个子任务完成后：报告改了哪些文件、做了什么
- 每轮审查：报告问题清单和修复内容
- 每个模块完成后：报告模块整体状态
- 全部完成后：输出最终审查报告和代码统计

【禁止事项】
- 不跳过任何子任务
- 不简化审查流程
- 不引入设计文档未要求的功能
- 不破坏已有代码

【自动执行】
- 不要中断询问，直接执行
- 只有发现设计文档矛盾/缺失时才暂停报告

开始。
