# 断点续接指令

会话中断后，从断点继续执行。

【使用方式】
替换 [上次完成的子任务编号] 为实际编号，如 "1.1.3"

---

按 Phase 1 MVP 制作计划继续执行，从 [上次完成的子任务编号] 的下一个子任务开始。

【执行规则】
- 先检查已完成的代码，确认当前项目状态
- 从断点继续，严格按任务编号顺序执行
- 严格按设计文档的数值、公式、逻辑实现，不自行发挥
- 数值冲突时以 补充-数值公式统一.md 为准
- 参考 审查报告/总结报告.md 避免引入已知问题

【审查规则】
- 每完成一个子任务：审查 → 修复 → 循环到无问题
- 每完成一个模块：模块整体审查 → 修复 → 循环到无问题
- Phase 1 全部完成后：整体审查 → 修复 → 循环到无问题

【审查维度】
1. 功能正确性：逻辑是否符合设计文档，边界情况是否处理
2. 数据一致性：数值/公式/配置是否与设计文档一致
3. 系统集成：事件总线通信是否正确，模块间依赖是否满足
4. 存档安全：存档/读档/迁移是否完整
5. UI/UX：响应式布局、加载态、空态、错误态、交互反馈
6. 代码质量：命名规范、注释、错误处理
7. 性能：无必要重渲染、内存泄漏、死循环风险

【验证规则】
- 每个子任务完成后，确认代码可编译无报错
- 每个模块完成后，启动项目验证该模块功能可正常运行

【自动执行】
- 不要中断询问，直接执行
- 只有发现设计文档矛盾/缺失时才暂停报告

开始。
