## 二、统一后的装备系统公式

### 2.1 品质系数表

| 品质 | 系数 | 打造概率 |
|------|------|---------|
| 普通（白） | 1.0 | 40% |
| 精良（绿） | 1.3 | 30% |
| 稀有（蓝） | 1.7 | 18% |
| 史诗（紫） | 2.2 | 9% |
| 传说（橙） | 3.0 | 2.5% |
| 神话（红） | 4.0 | 0.5% |
| 太古（金） | 5.0 | 三周目Boss掉落 + 进化 |

> **标准品质体系终点**：太古品质(5.0)是标准品质体系的最高品质，通过三周目内容获取。

> **无尽模式无限品质公式**（`04-装备系统.md` 与 `10-二周目与无尽模式.md` 一致）：

```
品质系数 = 1 + 0.5 × min(品质等级, 10) + 0.3 × max(0, 品质等级 - 10)
```

> **两套品质体系的关系**：标准品质（白→绿→蓝→紫→橙→红→太古）到太古5.0即为终点。无限品质是无尽模式专属的独立品质系统，从等级1开始（系数1.5），与标准品质体系无直接衔接关系。进入无尽模式后，装备品质切换为无限品质体系，原标准品质装备保留但不再提升品质等级。无限品质在无尽模式中完全替代标准品质。

### 2.3 强化系数公式

```
强化系数 = 1.25 ^ 强化等级

强化等级上限：
- 一周目：+15（硬上限）
- 二周目~五周目：+30（硬上限）
- 无尽模式：无硬上限，但+50以上采用衰减公式：
  +50以上：强化系数 = 1.25^50 × (1 + (强化等级-50) × 0.05)
  即+50之后每级增加固定5%而非乘以1.25
```

| 强化等级 | 系数 | 累计提升 |
|---------|------|---------|
| +0 | 1.00 | 0% |
| +3 | 1.95 | 95% |
| +6 | 3.81 | 281% |
| +9 | 7.45 | 645% |
| +12 | 14.55 | 1355% |
| +15 | 28.42 | 2742% |
| +30 | 807.79 | — |
| +50 | 70,065 | — |
| +60 | 105,097 | — |
| +100 | 245,227 | — |

> 衰减公式说明：+50之后指数增长转为线性增长，防止数值溢出。1.25^50 ≈ 70,065，之后每级在该基数上增加5%（即+51系数≈73,568，+52≈77,072...）。

### 2.4 强化消耗公式

```
强化石数量 = 境界等级 × (1 + 强化等级 × 0.1)
星币消耗 = 100 × 境界等级² × (1.2 ^ 强化等级)
```

| 强化等级 | 强化石（金丹30级基准） | 星币（金丹30级基准） |
|---------|----------------------|---------------------|
| +3 | 39颗 | 16万 |
| +6 | 48颗 | 27万 |
| +9 | 57颗 | 46万 |
| +12 | 66颗 | 80万 |
| +15 | 75颗 | 139万 |

> 注：`11-数值平衡总表.md` 中的消耗表（基于金丹30级）与公式一致。`04-装备系统.md` 中未列消耗表，以本公式为准。

### 2.5 强化成功率规则（统一版）

**两套规则矛盾点**：
- `04-装备系统.md`：三个段（+0~+100 / +101~+200 / +201+），失败规则简单
- `11-数值平衡总表.md`：五个段（+1~+50 / +50~+100 / +100~+150 / +150~+190 / +190+），有连续公式

**统一方案**：采用 `11-数值平衡总表.md` 的五段式成功率（更精细、更合理），但失败惩罚采用 `04-装备系统.md` 的三段式（更简洁、对玩家更友好）。

**成功率公式**：

```
成功率 = max(5%, 100% - 强化等级 × 0.5%)
```

| 强化段 | 成功率范围 | 说明 |
|--------|-----------|------|
| +1 ~ +50 | 100% ~ 75% | 基本必成 |
| +51 ~ +100 | 75% ~ 50% | 有失败风险 |
| +101 ~ +150 | 50% ~ 25% | 需要多次尝试 |
| +151 ~ +190 | 25% ~ 5% | 高风险区 |
| +190+ | 5%（保底） | 极限挑战 |

**失败惩罚规则**：

| 强化段 | 失败惩罚 | 保护符效果 |
|--------|---------|-----------|
| +0 ~ +100（含100） | 无变化 | — |
| +101 ~ +200（含200） | 降1级 | 不降级 |
| +201 及以上 | 降2级 | 只降1级 |

### 2.6 装备属性计算公式

强化后属性 = 装备基础属性 × 强化系数
```

## 五、Boss数值验证

### 5.1 验证前提

```
玩家属性 = 境界基础属性 + 装备属性
装备假设：当境界段稀有（蓝）品质 +3 强化（系数1.95）
技能假设：使用当前境界段最佳主动技能，倍率取平均2.5x
暴击假设：基础暴击率5%，暴击伤害150%
```

### 5.2 矿脉巨兽（练气10阶，等级10）

**玩家属性（练气10阶 + 稀有+3全套）**：
```
基础：攻击80，防御45，生命280

```

### 7.2 装备属性

```
装备基础属性 = 品质系数 × 部位系数 × 境界基数
强化后属性 = 装备基础属性 × 强化系数
强化系数 = 1.25 ^ 强化等级（+50以上采用衰减公式，见2.3节）
```

### 7.3 伤害计算

```
实际伤害 = 攻击 × 技能倍率 × (1 - 减伤率) × 暴击系数
减伤率 = 防御 ÷ (防御 + 1000 + 攻击方等级 × 50)
暴击系数 = 暴击时为 (1.5 + 暴击伤害加成)，否则为1
```

> 最低伤害保底规则：`最终伤害 = max(攻击 × 1%, 计算伤害)`，防止减伤率趋近100%时伤害归零。

### 7.4 强化系统

```
强化石消耗 = 境界等级 × (1 + 强化等级 × 0.1)
星币消耗 = 100 × 境界等级² × (1.2 ^ 强化等级)
成功率 = max(5%, 100% - 强化等级 × 0.5%)
失败惩罚：+0~+100（含100）无变化，+101~+200（含200）降1级，+201及以上降2级
```

### 7.5 生产效率

```
单次生产时间 = 基础时间 ÷ (1 + 设备等级 × 设备加速系数) ÷ (1 + 空间折叠器等级 × 0.1)

设备加速系数：熔炼炉/蒸馏器 = 0.2，萃取机/精炼台 = 0.15，炼丹炉/锻造台不适用（升级提升成功率/品质）
```

### 7.6 无尽模式怪物属性

```
1-100层：基础 × (1 + 层数 × 0.1)
101-500层：基础 × (11 + (层数-100) × 0.15)
501-1000层：基础 × (71 + (层数-500) × 0.2)
1001+层：基础 × (171 + (层数-1000) × 0.3)
Boss攻击 = 基础攻击 × (层数 ^ 1.2)
Boss防御 = 基础防御 × (层数 ^ 1.1)
Boss生命 = 基础生命 × (层数 ^ 1.5)
```

**Boss基础属性定义**：
- 基础攻击 = 渡劫10阶攻击 = 500,000
- 基础防御 = 渡劫10阶防御 = 250,000
- 基础生命 = 渡劫10阶生命 = 2,000,000

> 注：Boss基础属性固定为渡劫10阶玩家基础属性，不随玩家实际属性变化。

### 7.7 离线收益

```
离线采集 = 各星球产出速率 × 离线采集系数 × 离线时长
离线战斗 = 在线星币效率 × 0.3 × 离线时长

### 8.3 离线战斗规则

**离线时是否结算战斗**：✅ 是

```
离线战斗结算逻辑：
1. 记录离线时的玩家属性、装备、技能配置
2. 按离线时长计算击杀怪物数量
3. 产出星币和基础材料（不含Boss掉落、灵石、道韵）
4. 离线战斗效率 = 在线效率 × 30%
```

**离线战斗不产出的内容**：
- Boss掉落（需要在线挑战）
- 灵石（需要在线击杀Boss或副本）
- 道韵（需要在线击杀混沌Boss）
- 成就进度中的击杀计数（只计在线）
- 副本进度

**离线战斗产出的内容**：
- 星币（30%效率）
- 基础怪物掉落材料（30%效率）
- 星元（按修炼速率累积）

### 8.4 自动战斗与手动战斗的差异

| 维度 | 自动战斗 | 手动战斗 |
|------|---------|---------|
| 技能释放 | AI按优先级释放 | 玩家自主选择时机 |
| 技能命中 | 100%命中 | 100%命中 |
| 闪避/走位 | 无（站桩输出） | 可手动闪避Boss大招 |
| 生命丹使用 | 按阈值自动使用 | 玩家手动使用 |
| 战斗效率 | 100%（无惩罚） | 100% |
| Boss战 | 可开启但效率较低 | 推荐手动操作 |
| 副本 | 不可用 | 必须手动 |

> 放置游戏设计原则：自动战斗不设惩罚，手动操作的收益在于Boss战和副本的策略性，而非效率惩罚。

### 8.5 Boss刷新与自动挑战

```
Boss刷新机制：
  - 击杀后开始倒计时
  - 倒计时结束自动刷新
  - 玩家可设置"自动挑战Boss"（离线时也生效）

自动挑战Boss规则：
  - 只有历史击杀过的Boss才可自动挑战
  - 自动挑战使用当前装备和技能配置
  - 失败不扣次数，等Boss刷新后再次尝试
  - 掉落正常产出（区别于普通离线战斗）
  - 每日自动挑战次数上限：10次/Boss
```

## 十一、大数处理方案

### 11.1 问题说明

JavaScript `Number.MAX_SAFE_INTEGER = 2^53 ≈ 9×10^15`。
无尽模式强化系数 `1.25^1000 ≈ 2×10^96`，会溢出。

### 11.2 解决方案：ScientificNumber

内部存储格式：`{ mantissa: number, exponent: number, sign: -1 | 1, isZero: boolean }`
- mantissa 范围：[1, 10)
- exponent 范围：整数
- sign：符号位，默认1（正数）
- isZero：零标记，当 isZero=true 时 mantissa 和 exponent 忽略

#### 负数和零的表示

- sign 字段：`sign: -1 | 1`（默认1）
- isZero 标记：`isZero: boolean`（默认false）
- 当 `isZero=true` 时，mantissa 和 exponent 忽略，值恒为0
- 负数示例：`{ mantissa: 5.0, exponent: 3, sign: -1, isZero: false }` = -5000

#### 运算规则

| 运算 | 规则 |
|------|------|
| 乘法 | mantissa 相乘，exponent 相加，sign 相乘 |
| 除法 | mantissa 相除，exponent 相减，sign 相乘 |
| 加减法 | 先对齐 exponent 再运算 |
| 比较 | 先比 sign，再比 exponent，再比 mantissa |
| pow(exponent) | 幂运算，结果仍为 ScientificNumber |

#### 精度保护

- 加减法中，当两个操作数的 exponent 差 >= 16 时，直接返回较大的操作数（小数部分被忽略）
- 乘除法中，mantissa 使用 `Math.fround` 或直接 double 运算（JS 默认 64 位浮点精度足够）

#### 混合运算接口

```typescript
/** 将 number 或 ScientificNumber 统一转为 ScientificNumber */
function toSci(n: number | ScientificNumber): ScientificNumber

/** 大数加法 */
function sciAdd(a: ScientificNumber, b: ScientificNumber): ScientificNumber

/** 大数乘法 */
function sciMul(a: ScientificNumber, b: ScientificNumber): ScientificNumber

/** 大数转普通 number（有溢出风险时截断到 MAX_SAFE_INTEGER） */
function sciToNumber(s: ScientificNumber): number
```

**UI 显示规则：**

| exponent 范围 | 显示格式 | 示例 |
|---------------|---------|------|
| < 4 | 普通数字 | 1,234 |
| 4 ≤ exp < 8 | 万 | 1.23万 |
| 8 ≤ exp < 12 | 亿 | 1.23亿 |
| 12 ≤ exp < 16 | 兆 | 1.23兆 |
| ≥ 16 | 科学计数法 | 1.23e45 |

### 11.3 适用范围

| 周目/模式 | 是否需要 ScientificNumber | 说明 |
|----------|--------------------------|------|
| 一周目（+15 强化以内） | 否 | 普通 Number 足够 |
| 二周目 - 五周目 | 建议 | 部分数值可能接近边界，建议提前切换 |
| 无尽模式 | 必须 | 1.25^1000 已溢出 |

**切换阈值**：当任何数值超过 `1e14` 时自动切换至 ScientificNumber。
