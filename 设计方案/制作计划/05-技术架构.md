# 技术架构设计

## 一、技术选型

| 层级 | 选型 | 说明 |
|------|------|------|
| 渲染 | DOM + CSS Grid | 零配置，适合UI密集型放置游戏 |
| 状态管理 | 全局对象 + 发布/订阅事件 | 简单直接，无框架依赖 |
| 存储 | localStorage | 浏览器原生，零依赖 |
| 构建 | 无 | 双击 index.html 直接运行 |
| 部署 | GitHub Pages | 免费静态托管 |
| 大数 | ScientificNumber 自实现 | 防止无尽模式数值溢出 |

## 四、模块通信机制

### 4.1 事件总线（发布/订阅）

```javascript
/**
 * EventBus - 轻量级事件总线
 *
 * 设计原则：
 * - 系统间不直接调用，全部通过事件解耦
 * - 事件名为字符串，采用 "模块:动作" 命名规范
 * - 支持一次性订阅（once）和优先级
 */
class EventBus {
  constructor() {
    this._listeners = new Map();   // event -> Set<{handler, priority, once}>
  }

  /**
   * 订阅事件
   * @param {string} event - 事件名
   * @param {Function} handler - 回调 (data) => void
   * @param {object} options - { priority: number, once: boolean }
   */
  on(event, handler, options = {}) {}

  /** 一次性订阅 */
  once(event, handler) {}

  /** 取消订阅 */
  off(event, handler) {}

  /**
   * 触发事件（同步执行所有订阅者，按priority降序）
   * @param {string} event - 事件名
   * @param {*} data - 事件数据
   */
  emit(event, data) {}
}
```

## 五、游戏主循环

### 5.1 主循环架构

```javascript
/**
 * 游戏主循环
 *
 * 每秒执行一次tick，按顺序更新各系统，最后刷新UI。
 * 采用固定步长（1秒），不使用requestAnimationFrame（放置游戏不需要60fps）。
 */
function gameLoop(timestamp) {
  const dt = timestamp - Game.loop.lastTick;  // 实际间隔（ms）
  Game.loop.lastTick = timestamp;

  // 1. 更新修炼进度
  Game.systems.realm.update(dt);

  // 2. 更新采集进度
  Game.systems.resource.update(dt);

  // 3. 更新生产队列
  Game.systems.production.update(dt);

  // 4. 更新战斗（自动战斗/Boss/副本）
  Game.systems.combat.update(dt);

  // 5. 更新入侵倒计时与怪物移动
  Game.systems.invasion.update(dt);

  // 6. 更新灵田生长
  Game.systems.planet.updateFarm(dt);

  // 7. 更新天气系统
  Game.systems.planet.updateWeather(dt);

  // 8. 更新科技研究进度
  Game.systems.tech.update(dt);

  // 9. 检查任务/成就触发
  Game.systems.quest.update(dt);
  Game.systems.achievement.update(dt);

  // 10. 刷新UI（仅当前可见页面）
  Game.ui.renderCurrentPage();

  // 11. 触发tick事件（供其他模块监听）
  Game.events.emit('game:tick', { timestamp });
}
```

### 5.2 启动流程

```javascript
/**
 * 游戏启动流程
 *
 * 1. 加载配置表
 * 2. 加载存档（或创建新存档）
 * 3. 计算离线收益
 * 4. 初始化各系统
 * 5. 初始化UI
 * 6. 启动主循环
 * 7. 启动自动保存
 */
async function initGame() {
  // 1. 加载配置（config.js已内嵌，直接挂载）
  loadConfig();

  // 2. 加载存档
  const savedState = Game.systems.save.load();
  if (savedState) {
    Game.state = savedState;
    // 3. 计算离线收益
    const offlineRewards = Game.systems.offline.calculate(Game.state);
    if (offlineRewards.offlineSeconds > 60) {
      showOfflineRewardModal(offlineRewards);
    }
  } else {
    Game.state = createNewPlayerState();
  }

  // 4. 初始化系统（注入依赖）
  initSystems();

  // 5. 初始化UI
  initUI();

  // 6. 启动主循环
  Game.loop.running = true;
  Game.loop.lastTick = Date.now();
  Game.loop.tickInterval = setInterval(() => gameLoop(Date.now()), 1000);

  // 7. 启动自动保存
  Game.loop.saveInterval = setInterval(() => {
    Game.systems.save.save(Game.state);
  }, 30000);

  // 8. 绑定页面关闭保存
  window.addEventListener('beforeunload', () => {
    Game.systems.save.save(Game.state);
  });
  document.addEventListener('visibilitychange', () => {
    if (document.hidden) {
      Game.systems.save.save(Game.state);
    }
  });
}
```

### 5.3 Tick时序图

```
时间轴（每秒1次tick）：

  ┌─ 0ms: tick开始
  │
  ├─ 境界系统：检查星元是否足够自动积累
  ├─ 资源系统：更新自动采集进度条，满则产出
  ├─ 生产系统：检查队列中是否有完成项
  ├─ 战斗系统：执行自动战斗回合（如果在挂机）
  ├─ 入侵系统：更新怪物移动/攻击，检查波次间隔
  ├─ 灵田系统：检查作物是否成熟
  ├─ 天气系统：倒计时，触发随机天气事件
  ├─ 科技系统：研究点积累
  ├─ 任务系统：检查当前任务完成条件
  ├─ 成就系统：检查各成就进度
  │
  ├─ UI渲染：仅更新当前可见页面的DOM
  │
  └─ 0ms→1000ms: 等待下次tick
```

```javascript
 * 版本迁移策略
 *
 * 1. 存档写入时附带当前 SAVE_VERSION
 * 2. 读取时检测版本号，逐级执行迁移函数
 * 3. 迁移链：v0 → v1 → v2 → ...
 * 4. 每个迁移函数只负责"上一版 → 本版"的差异补全
 * 5. 新增字段必须提供默认值
 * 6. 迁移失败保留原存档副本（key: backup_<timestamp>）
 */

const SAVE_VERSION = 1;

const MIGRATION_CHAIN = [
  // v0 → v1：初始化所有字段默认值
  migrateV0ToV1,
  // v1 → v2：示例（未来扩展）
  // migrateV1ToV2,
];

function migrateIfNeeded(data) {
  let version = data.version ?? 0;
  for (let i = version; i < MIGRATION_CHAIN.length; i++) {
    data = MIGRATION_CHAIN[i](data);
  }
  data.version = SAVE_VERSION;
  return data;
}
```

### 6.4 存档防篡改

```javascript
/**
 * 防篡改方案（轻量级，纯前端）
 *
 * 1. 校验和：存档附带CRC32摘要，加载时校验
 * 2. 数值上界：货币/属性超出合理范围时标记异常
 * 3. 简单加密：XOR混淆，防止手改JSON
 */
function addChecksum(stateJson) {
  const checksum = crc32(stateJson);
  return JSON.stringify({ data: JSON.parse(stateJson), checksum });
}
```

```javascript
/**
 * 计算玩家最终属性
 * 基础属性（境界）+ 装备加成 + 功法加成 + 成就加成 + 科技加成
 */
function calculatePlayerStats(state) {
  const realmStats = getRealmStats(state.realm.level);
  const equipBonus = calculateEquipmentBonus(state);
  const skillBonus = calculateSkillBonus(state);
  const achievementBonus = calculateAchievementBonus(state);
  const techBonus = calculateTechBonus(state);

  return {
    attack:  (realmStats.atk  + equipBonus.atk)  * (1 + skillBonus.atkPct  + achievementBonus.atkPct  + techBonus.atkPct),
    defense: (realmStats.def  + equipBonus.def)  * (1 + skillBonus.defPct  + achievementBonus.defPct  + techBonus.defPct),
    hp:      (realmStats.hp   + equipBonus.hp)   * (1 + skillBonus.hpPct   + achievementBonus.hpPct   + techBonus.hpPct),
    critRate:     clamp(equipBonus.critRate     + skillBonus.critRate,     0, 0.8),
    critDamage:   clamp(equipBonus.critDamage   + skillBonus.critDamage,   0, 3.0),
    penetration:  clamp(equipBonus.penetration  + skillBonus.penetration,  0, 0.75),
    dodgeRate:    clamp(equipBonus.dodgeRate    + skillBonus.dodgeRate,    0, 0.5),
    hpRegen:      realmStats.hpRegen + equipBonus.hpRegen,
  };
}
```

### 8.2 伤害计算

```javascript
/**
 * 核心伤害公式
 */
function calculateDamage(attacker, defender, skillMultiplier = 1.0) {
  // 穿透计算
  const effectiveDefense = defender.defense * (1 - clamp(attacker.penetration, 0, 0.75));

  // 减伤率
  const reductionRate = effectiveDefense / (effectiveDefense + 1000 + attacker.level * 50);

  // 暴击判定
  const isCrit = Math.random() < attacker.critRate;
  const critMultiplier = isCrit ? (1.5 + attacker.critDamage) : 1.0;

  // 基础伤害
  let damage = attacker.attack * skillMultiplier * (1 - reductionRate) * critMultiplier;

  // 最低保底
  damage = Math.max(attacker.attack * 0.01, damage);

  return { damage: Math.floor(damage), isCrit };
}
```

## 九、错误处理与降级

### 9.1 存档安全

```javascript
/**
 * 存档写入保护
 * 1. 写入前先尝试序列化，失败则不覆盖
 * 2. 写入后立即读回校验
 * 3. 保留3个滚动备份
 */
function safeSave(state) {
  try {
    const json = JSON.stringify(state);
    const checksum = crc32(json);
    const payload = JSON.stringify({ data: JSON.parse(json), checksum, version: state.version });

    // 写入主存档
    localStorage.setItem(SAVE_KEY, payload);

    // 校验写入
    const readback = localStorage.getItem(SAVE_KEY);
    if (!readback) throw new Error('写入后读回失败');

    // 滚动备份
    const backupKey = `${BACKUP_PREFIX}${Date.now()}`;
    localStorage.setItem(backupKey, payload);
    pruneOldBackups(3);

    return true;
  } catch (e) {
    console.error('[存档] 保存失败:', e);
    return false;
  }
}
```

## 十、性能优化策略

| 策略 | 说明 |
|------|------|
| 按需渲染 | 只渲染当前可见页面，切换时销毁旧页面DOM |
| 事件委托 | 导航栏、列表等使用事件委托，减少监听器数量 |
| 节流更新 | 数字跳动使用CSS动画而非每帧重绘 |
| 惰性计算 | 属性缓存，仅在装备/境界变更时重算 |
| 配置只读 | config.js内容加载后冻结，避免意外修改 |
| 批量DOM | 使用innerHTML批量构建，避免逐个createElement |
| 存档压缩 | 默认值字段不写入JSON，减少序列化体积 |
